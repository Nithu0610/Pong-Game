## 5. Version Interview Talking Points

```
PONG GAME - Interview Preparation

OPENING PITCH (60 seconds):
"I built a Pong game using vanilla JavaScript, HTML5 Canvas, and CSS3. It features both 
multiplayer and AI modes. The interesting part is the AI system—it uses trajectory prediction 
to calculate where the ball will be, accounting for bounces off walls. I implemented 4 difficulty 
levels by varying the AI's speed and accuracy. The whole thing is optimized to 60 FPS and has 
zero external dependencies."

KEY POINTS TO EMPHASIZE:
1. Vanilla JavaScript - Shows understanding of fundamentals
2. AI Algorithm - Demonstrates algorithmic thinking
3. Physics - Shows math/physics knowledge
4. Performance - Proved optimization skills
5. Responsive Design - Full-stack awareness

QUESTIONS YOU MIGHT GET:

Q: "Walk me through the AI algorithm"
A: "The AI tracks the ball's position and velocity. When it detects the ball moving toward it, 
it calculates when and where it will arrive by projecting the Y position forward in time. It 
accounts for bounces if the trajectory goes out of bounds. Then it adds intentional error based 
on difficulty—easy mode has large error, hard mode has almost none. This makes it believable 
and adjustable."

Q: "Why vanilla JavaScript instead of a framework?"
A: "For a project like this, vanilla JS is actually better—it demonstrates real understanding 
of JavaScript fundamentals and the browser APIs. It also shows I can evaluate whether a tool is 
necessary rather than reaching for frameworks by default."

Q: "How would you extend this to multiplayer online?"
A: "I'd add a WebSocket connection to a Node.js server. The tricky part is handling latency—
I'd implement client-side prediction and server-side rollback to handle lag. Each client would 
render 60 FPS while syncing state with the server at maybe 30 Hz."

Q: "What's the most complex part?"
A: "Definitely the trajectory prediction in the AI. Calculating where the ball will be while 
accounting for multiple wall bounces requires careful math to handle edge cases. I also had to 
optimize it to run in <1ms to not drop frames."

QUESTIONS TO ASK BACK:
- "Do you hire contract/project work?"
- "What does your tech stack look like?"
- "How important are performance and optimization in your role?"
```
